## 1. 本章解决什么问题

数据量小的时候，用文件存就行了。那**为什么还需要数据库**？

文件系统的三个死结：

1. **冗余与不一致**：同一份学生信息，教务处存一份、图书馆存一份，改了一处忘另一处；
2. **没有并发控制**：两个人同时写同一个文件，后写的覆盖先写的；
3. **没有统一的查询语言**：换个需求就得重写程序，无法「声明要什么」而不关心「怎么取」。

数据库系统的答案是：**把数据从「程序里的文件」变成「被统一管理的数据集合」**，
由一个 DBMS 负责存储、查询、并发、恢复、权限。我只要描述**要什么**。

## 2. 核心概念（用自己的话）

| 术语 | 我的解释 | 类比 |
|---|---|---|
| 数据库 (DB) | 长期存储在计算机内、有组织、可共享的数据集合 | 一个仓库 |
| DBMS | 管理数据库的软件，负责存取、并发、恢复、权限 | 仓库管理员 + 规章制度 |
| DBS | DB + DBMS + 应用程序 + DBA + 用户 | 整个公司 |
| 数据模型 | 数据结构 + 数据操作 + 完整性约束 | 仓库的货架设计图 |
| 模式 (Schema) | 全体数据的逻辑结构，相对稳定 | 仓库的货架布局图 |
| 外模式 | 用户看到的那部分数据视图 | 每个部门的取货清单 |
| 内模式 | 数据在磁盘上怎么存 | 货架的物理位置 |

### 三级模式两级映像

```
外模式1  外模式2        ← 每个用户/应用看到的
   \      /
     模式              ← 全局逻辑结构（表、视图定义）
      |
    内模式             ← 存储结构（文件、索引、页）
```

- **外模式/模式映像** → 逻辑独立性：改表结构，只要改映像，应用不用动；
- **模式/内模式映像** → 物理独立性：加索引、换存储引擎，逻辑结构不用动。

理解这两个「独立性」是第 1 章唯一真正要记住的东西，其余都是名词。

## 3. 关系模型三要素

- **数据结构**：一张二维表（关系），行是元组，列是属性；
- **数据操作**：关系代数 / 关系演算（SQL 是二者的混合）；
- **完整性约束**：
  - 实体完整性：主码不能为空、不能重复；
  - 参照完整性：外码要么为空，要么等于被参照表里存在的值；
  - 用户定义完整性：CHECK、NOT NULL 这类业务规则。

### 关系代数五种基本运算

| 运算 | 符号 | SQL 对应 | 说明 |
|---|---|---|---|
| 选择 | σ | `WHERE` | 挑行 |
| 投影 | π | `SELECT 列` | 挑列（自动去重） |
| 并 | ∪ | `UNION` | 要求属性数、类型相同 |
| 差 | − | `EXCEPT` | 在 A 不在 B |
| 笛卡尔积 | × | `CROSS JOIN` | 行数相乘，几乎总要先接选择 |

派生运算：交（∩）、连接（⋈）、除（÷）。**连接 = 笛卡尔积 + 选择**，
**除 = 「对所有…都…」**，SQL 里用双重 `NOT EXISTS` 实现。

## 4. 我踩过的坑

```sql
-- 坑 1：投影后的重复行
-- 关系代数里 π 是集合语义，自动去重；SQL 的 SELECT 默认是包语义，不去重。
SELECT Sdept FROM Student;        -- 4 行，CS 出现 2 次
SELECT DISTINCT Sdept FROM Student;  -- 3 行
```

```sql
-- 坑 2：外码约束要求被参照的值先存在
INSERT INTO Student(Sno, Sname, Ssex, Sage, Sdept) VALUES ('200215126','测试','男',20,'CS');
INSERT INTO SC(Sno, Cno, Grade) VALUES ('200215999','1',90);
-- ERROR 1452: Cannot add or update a child row: a foreign key constraint fails
-- 原因：SC 里引用的学号在 Student 中不存在
```
